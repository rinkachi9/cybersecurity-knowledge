## What it is?

A **hashing algorithm** is a mathematical function that transforms input data of any size into a fixed-size string of characters, typically a combination of letters and numbers. This output is called a **hash value**, **hash code**, or **digest**. Hashing algorithms are deterministic, meaning the same input will always produce the same hash output.

### Key components

1. **Input Data**: The data to be hashed, which can be of any size or type (e.g., text, files, binary data).
2. **Hash Function**: The algorithm that processes the input data.
3. **Hash Value**: The fixed-size output generated by the hash function.

Example: If the input data is "hello world", a hashing algorithm like SHA-256 will produce a specific 64-character hash:

```text
SHA-256("hello world") = b94d27b9934d3e08a52e52d7da7dabfa4a1f9d08...
```

### Purpose

- **Fixed Representation**: Converts variable-length data into a fixed-size output.
- **Uniqueness**: Ideal hashing algorithms aim to produce unique outputs for unique inputs (minimizing collisions).
- **One-Way Functionality**: It is computationally infeasible to reverse-engineer the input data from its hash.

### Key properties

1. **Deterministic**: The same input will always result in the same hash value.
2. **Fixed Output Size**: Regardless of the input size, the output length is constant.
3. **Non-Reversible**: The hash function is one-way; you can’t deduce the input from the output.
4. **Collision-Resistant**: Ideally, no two different inputs should produce the same hash (though collisions are possible in practice for weak algorithms).

### Hashing vs encryption

- **Hashing**: One-way process; used for validation and integrity checks.
- **Encryption**: Two-way process; used to secure communication where data can be decrypted back to its original form.

## Purpose

Hashing algorithms serve a variety of purposes across different domains, from ensuring data integrity to enhancing security.

### Data Integrity

Hashing ensures that data remains unaltered during storage or transmission. By comparing the hash of the received data with the original hash:

- **Verification**: If the hashes match, the data has not been tampered with.
- **Example**:
  - File downloads often provide a hash (e.g., SHA-256) for users to verify the integrity of the downloaded file.
  - In network communications, checksums (a form of hash) detect errors in transmitted data.

#### Efficient Data Lookup

Hashing enables fast data retrieval in data structures like hash tables and hash maps:

- **Key-Value Mapping**: Hashing functions map keys to specific positions in a table, enabling quick access.
- **Applications**:
  - Caches (e.g., Redis, Memcached).
  - Database indexing for faster queries.

##### Password Security

- Hashing algorithms protect sensitive information like passwords:
  - Passwords are stored as hashes rather than plaintext.
  - During authentication, the system hashes the entered password and compares it with the stored hash.
- Techniques for added security:
  - **Salting**: Adding a random value to the input before hashing to prevent precomputed attacks (e.g., rainbow tables).
  - **Key-Stretching Algorithms**: Examples include bcrypt, Argon2, and PBKDF2.

##### Cryptography

Hashing is fundamental in securing digital communications and data:

1. **Digital Signatures**:
   - Hashing ensures that a document or message is not altered.
   - The hash is encrypted with a private key to create the signature.
2. **Message Authentication Codes (MACs)**:
   - Combines a hash with a secret key to verify message integrity and authenticity.
3. **Blockchain**:
   - Hashing secures transaction data.
   - Example: Bitcoin uses SHA-256 to link blocks in a chain.

##### Data Deduplication

Hashing helps identify and eliminate duplicate data:

**Applications**:

- Backup systems and storage solutions compare hashes to detect duplicates.
- File synchronization tools (e.g., rsync).

##### File Verification

**Use Case**: Verifying software or file authenticity.

Example: Open-source projects often provide file hashes (e.g., MD5 or SHA-256) so users can confirm the file’s authenticity after downloading.

##### Forensic Applications

Hashing is widely used in digital forensics to:

- Detect file alterations or tampering.
- Generate unique hashes for evidence identification.

##### Proof-of-Work Systems

Hashing underpins systems like blockchain mining:

Miners solve a computationally expensive hash puzzle to create a new block (e.g., Bitcoin mining with SHA-256).

##### Load Balancing and Data Distribution

Hashing algorithms distribute workloads or data evenly across systems:

Example: Consistent hashing in distributed systems ensures data is evenly distributed across nodes.

##### Examples

| **Scenario** | **Hashing Role** |
| --- | --- |
| **Password Storage** | Ensures passwords are securely stored as hashes. |
| **Data Transmission (e.g., files)** | Verifies data integrity using checksum or hash (e.g., SHA-256). |
| **Blockchain** | Secures transactions and links blocks using cryptographic hashes. |
| **Caching** | Quickly retrieves cached data based on a hashed key. |
| **Forensic Investigations** | Detects tampered files by comparing hashes. |

## Characteristics

Hashing algorithms are designed to meet specific requirements for various applications. Below are their key characteristics, which define their functionality and usefulness.

### Deterministic

The same input always produces the same hash output.

**Example**: Hashing "hello world" with SHA-256 will always result in the same fixed hash value.

**Importance**: Ensures consistency, making hashing reliable for data verification.

#### Fixed Output Length

Regardless of the size of the input, the output hash has a fixed length.

**Example**:

- SHA-256 always produces a 256-bit (64-character) hash.
- MD5 always produces a 128-bit (32-character) hash.

**Importance**: This property is critical for consistency in applications like cryptography and data storage.

##### One-Way Function

It is computationally infeasible to reverse a hash to its original input.

**Example**: Given a hash like `5eb63bb...`, you cannot deduce the input string "hello world."

**Importance**: This property makes hashing secure for password storage and digital signatures.

##### Fast Computation

Hash functions are designed to be computationally efficient.

**Importance**: This allows for quick data verification, making hashing suitable for high-performance systems.

##### Avalanche Effect

A small change in the input results in a significantly different hash.

**Example**:

- SHA-256("hello world") = `b94d27b993...`
- SHA-256("hello worlD") = `ec4ac3b23e...`

**Importance**: This ensures that even minimal changes in the input are detectable.

##### Collision Resistance

It is difficult to find two different inputs that produce the same hash.

**Example**: Ideally, "apple" and "banana" should never produce the same hash value.

**Importance**: Essential for cryptographic security, digital signatures, and data integrity.

**Note**: Some outdated algorithms like MD5 and SHA-1 are no longer collision-resistant.

##### Uniform Distribution

Hash values should be evenly distributed across the output space.

**Example**: Hashing a set of numbers (1, 2, 3, ...) should result in widely varying hash values, not a predictable sequence.

**Importance**: Prevents clustering in hash tables and ensures efficient data storage and retrieval.

##### Pre-Image Resistance

Given a hash value, it should be infeasible to determine the original input.

**Importance**: Protects hashed data like passwords from being reverse-engineered.

##### Second Pre-Image Resistance

It is computationally infeasible to find a second input that produces the same hash as a given input.

**Example**:

- If `SHA-256("hello") = 2cf24dba...`, it should be impossible to find another string `x` such that `SHA-256(x) = 2cf24dba...`.

**Importance**: Critical for cryptographic applications to avoid data forgery.

##### Scalability

Hashing algorithms should handle varying input sizes efficiently.

**Importance**: Enables hashing large datasets or streaming data without performance degradation.

##### Platform Independence

Hashing algorithms must produce the same output regardless of the hardware or software platform.

**Importance**: Ensures consistent results in distributed systems.

##### Practical examples

| **Characteristic** | **Example/Explanation** |
| --- | --- |
| Deterministic | Input "hello" always produces the same hash (e.g., SHA-256). |
| Fixed Output Length | Input of any size (1 KB or 1 GB) produces the same-sized hash (e.g., 256-bit). |
| One-Way Function | Hashing cannot reveal the original input. |
| Avalanche Effect | Input "hello" vs. "Hello" gives vastly different hashes. |
| Collision Resistance | No two inputs (ideally) produce the same hash. |

##### Characteristics exmplanation

1. **Security**: Protect sensitive data by ensuring it cannot be reverse-engineered.
2. **Efficiency**: Enable fast data verification and retrieval.
3. **Reliability**: Consistent results across platforms and systems.
4. **Accuracy**: Detect even minor data modifications.

## Types

Hashing algorithms can be broadly categorized into two main types: **cryptographic** and **non-cryptographic**. Each type serves different purposes and has specific characteristics.

### Cryptographic hash functions

These are designed with security in mind and are widely used in cryptography and data security.

#### Characteristics

- Strong collision resistance.
- Pre-image resistance (hard to reverse the hash).
- Avalanche effect (small input change causes large output difference).
- Deterministic output.

##### Algorithms

1. **SHA Family (Secure Hash Algorithm)**:
   - **SHA-1**: Produces a 160-bit hash; considered insecure due to vulnerability to collisions.
   - **SHA-2**: Includes variants like SHA-256 and SHA-512. Commonly used in blockchain, SSL certificates, and cryptographic applications.
   - **SHA-3**: Based on the Keccak algorithm; resistant to quantum computing threats.
2. **MD5 (Message Digest Algorithm 5)**:
   - Produces a 128-bit hash.
   - Fast but insecure due to known vulnerabilities and susceptibility to collisions.
3. **Bcrypt**:
   - Specifically designed for password hashing.
   - Adds a computational cost (key-stretching) to resist brute-force attacks.
4. **Argon2**:
   - Winner of the Password Hashing Competition (PHC).
   - Highly secure, resistant to side-channel attacks.
5. **Whirlpool**:
   - Produces a 512-bit hash.
   - Strong cryptographic properties.
6. **RIPEMD**:
   - A family of cryptographic hash functions (e.g., RIPEMD-160).
   - Less commonly used but still secure.

##### Use cases

- Password hashing (Bcrypt, Argon2).
- Digital signatures (SHA-2, SHA-3).
- Blockchain and cryptocurrencies (SHA-256 in Bitcoin).
- Verifying software integrity.

#### Non-Cryptographic hash functions

These are designed for speed and efficiency, not for security. They are widely used in scenarios where performance is more critical than security.

##### Characteristics

- Fast computation.
- Collision resistance is less critical.
- Not suitable for cryptographic applications.

##### Algorithms

1. **MurmurHash**:
   - Known for its speed and uniform distribution.
   - Common in hash tables and databases.
2. **CityHash**:
   - Optimized for performance on modern CPUs.
   - Used in applications requiring fast hashing of large data.
3. **FNV (Fowler-Noll-Vo)**:
   - Simple and efficient, commonly used in hash tables.
4. **CRC (Cyclic Redundancy Check)**:
   - Designed for error detection in data transmission.
   - Used in file systems, networking, and storage.

##### Use cases

- Hash tables and dictionaries (MurmurHash, CityHash).
- Data deduplication.
- Load balancing in distributed systems.
- Error checking in data transmission (CRC).

#### Comparison

| **Feature** | **Cryptographic** | **Non-Cryptographic** |
| --- | --- | --- |
| **Primary Focus** | Security | Speed and efficiency |
| **Collision Resistance** | High | Moderate or low |
| **Use Cases** | Passwords, digital signatures, SSL | Hash tables, checksums, data deduplication |
| **Performance** | Slower | Faster |

#### Specialized hashing algorithms

1. **Keyed Hashes**:
   - **HMAC (Hash-Based Message Authentication Code)**:
     - Combines a hash function with a secret key.
     - Used for message authentication and integrity.
2. **Rolling Hashes**:
   - Allows efficient re-hashing of data streams.
   - Example: Rabin-Karp algorithm for string matching.
